# MO2 ApI Bridge

Локальный HTTP API внутри работающей Mod Organizer 2 для скриптов и ИИ-агентов.

**Кандидат разработки 2.3.6; не выпущен.** Стабильный выпуск в `main` —
[2.3.5](https://github.com/Vhodnoylogin/MO2-ApI-Bridge/releases/tag/v2.3.5).
Кандидат исправляет выборочную распаковку допустимых архивов с пустыми полями последнего
каталога и отличает историческую запись установки от текущих штатных метаданных.
Для RAR4/RAR5 добавлены отдельные проверки наряду с ZIP и 7z.
Новая проверка кандидата в живой MO2 пока не проводилась.

По результатам потребительских проверок добавлены штатное сохранение метаданных
до проверки ID исходного файла и удаление через полный путь модели MO2.
Перед выпуском этим исправлениям нужна проверка точного пакета в живой MO2.

[English version](README.md) · [Документация API](src/main/plugin_mo2aibridge/README.ru.md)
· [Проверки](src/test/README.ru.md)

Выборочная штатная установка включается явно и рассчитана на MO2 2.5.2. Вызывающий
выбирает варианты FOMOD и проверяет рекурсивные требования и совместимость с runtime;
Bridge исполняет явный выбор и проверяет учёт исходного архива. Самостоятельные моды и
их зависимости устанавливаются отдельно. Генерируемые результаты хранятся в отдельных модах.

Архитектурная проверка отделяет чистые правила архивов, выбора файлов и истории
установки от управления MO2. Временными ресурсами 7-Zip управляет один класс;
изменение активности плагинов сохраняет остальные байты профиля. Проверка запуска
предшествует созданию процесса. Проверка обновлений учитывает игру на Nexus и
повторно использует успешный ответ страницы в пределах одного запроса.
Процент ускорения и новая проверка в настоящей MO2 не заявляются.

## Исходники и выпуск

```text
src/main/plugin_mo2aibridge/  рабочий Python-пакет, переводы, инструкции, лицензия MIT
src/main/pack.py             исходник упаковщика
src/test/                   исходники проверок и синтетические примеры
target/                     игнорируемые результаты сборки
```

Выпущенные исходники и тесты хранятся в `main`, дальнейшая разработка — в одной ветке
`develop`. Пользовательский ZIP содержит рабочий пакет, необходимые инструкции и лицензию.
Инструкции сборки, тестовые примеры и инструменты разработки остаются в репозитории.
Исходная история `Skyrim-Mods/mo2aibridge` сохранена.

## Установка

Распаковать архив выпуска в `<MO2>/plugins/`, получив
`<MO2>/plugins/mo2aibridge/__init__.py`. MO2 выводит имя Python-пакета из установленной
папки: она должна называться `mo2aibridge`. Копирование всего репозитория плагин не устанавливает.
При разработке скопировать `src/main/plugin_mo2aibridge/` или создать на неё junction
по указанному пути установки. Перезапустить MO2 для загрузки нового кода.

## Сборка и проверка

Из корня репозитория:

```text
python src/test/run.py --offline
python src/main/pack.py
```

Упаковщик создаёт `target/release/mo2aibridge-<version>.zip`; другой каталог можно передать
аргументом. Разрешённый состав — рабочие `.py`, оба пользовательских README, `LICENSE`
и всё дерево переводов. Токены, настройки, журналы, тесты и bytecode исключены из Git и архива.

Автономные проверки не обращаются к менеджеру владельца. Дополнительные Qt-проверки
требуют PyQt6. `python src/test/run.py` запускать только с предназначенной для проверки
тестовой MO2: живые наборы могут менять её временные данные. Пропуск набора не означает
проверку работы плагина в MO2. `MO2AIBRIDGE_LANG=ru` включает русский вывод проверок.
